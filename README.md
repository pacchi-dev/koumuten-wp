# ソラノワ工務店 コーポレートサイト（WordPress・オリジナルテーマ）

> ## ⚠ 本サイトは架空の企業を想定した制作サンプルです
>
> **「株式会社ソラノワ工務店」は実在しません。**
> 社名・住所・電話番号・建設業許可番号・沿革・施工実績はすべて架空のものです。
> 掲載している写真は Pexels / Unsplash のフリー素材であり、**実在の施工事例ではありません**。
> 実在の企業・団体・物件とは一切関係ありません。

WordPress 案件への応募用に制作した、工務店のコーポレートサイトです。
既製テーマを使わず、テーマとプラグインを自作しています。

| | |
|---|---|
| 種別 | オリジナルテーマ + 自作プラグイン |
| WordPress / PHP | 7.1 / 8.3 |
| 実行環境 | Docker（ローカル完結。公開はしていません） |
| 想定業種 | 工務店（注文住宅・リノベーション） |

## 1. 何を証明するための制作物か

別途公開しているポートフォリオ（`portfolio_wordpress`）はダークテーマのエンジニア向けサイトで、
写真を使ったレイアウトがありません。本制作で示したいのは次の 3 点です。

1. 明るい配色の、一般的な企業サイトが作れること
2. 写真を主役にしたレイアウトができること
3. 非エンジニアのクライアント向けのサイトが作れること

### なぜ工務店を題材にしたか

CrowdWorks の「WordPress 制作・導入」143 案件を調査したところ、
**業種経験を明示的に応募条件にしていた唯一の業種が建設業**でした。

> 「建設業のホームページを3社程度作成された経験をお持ちの方希望です。
>  ポートフォリオの提示をお願いいたします」（約30万円の案件）

## 2. 設計の根拠（推測ではなく実測）

工務店・建設会社 68 サイトを訪問し、うち WordPress 50 件を構造解析しました。
**このサイトの主要な設計判断は、すべてその実測値に紐づいています。**

| 実測値 | この制作物への反映 |
|---|---|
| WordPress 率 74%、うち**オリジナルテーマ 76%**、既製テーマ（SWELL / Lightning / Elementor 等）**0 件** | オリジナルテーマで制作。業界標準に合わせた |

| トップページの `<img>` 枚数が**中央値 55 枚** | 画像最適化を最重要要件に設定（→ 6章） |
| ヘッダー内に電話番号があるサイト **0 件** | ヘッダーは「お問い合わせ」ボタン。電話番号はフッター・CTA帯・お問い合わせページ |

## 4. 責務の分離

| | 置き場所 | 理由 |
|---|---|---|
| CPT・タクソノミー・ACF 定義・会社情報設定 | プラグイン `koumuten-core` | **テーマを差し替えてもデータが残る必要がある** |
| テンプレート・CSS・SEO 出力・間取り図描画 | テーマ `soranowa-koumuten` | 表示の責務 |

数年後に「デザインだけリニューアルしたい」となったとき、テーマの差し替えだけで済みます。

### 施工実績のデータ構造

投稿タイプ `work`（スラッグ `works`）＋ タクソノミー 2 種。

- `work_category`（種別）: 注文住宅 / リノベーション / 増改築 / 外構
- `work_area`（エリア）: 姫路市 / たつの市 / 加古川市 / 高砂市

種別とエリアを 1 つのタクソノミーにまとめると「注文住宅かつ姫路市」の絞り込みができないため分けています。
タームのスラッグは英字を明示しています（日本語のままだと URL がパーセントエンコードされて読めなくなるため）。

ACF フィールド（所在地 / 竣工年月 / 構造・規模 / 敷地面積 / 延床面積 / 家族構成 / 工期 / 間取り）は、
実サイト（松尾工務店・ネイエ設計）の物件概要テーブルの実測に準拠しています。

## 5. 施工実績の詳細ページ

### 「松尾工務店型」を採用した理由

実サイトの詳細ページは画像枚数に大きな幅がありました。

| サイト | 詳細ページの画像枚数 |
|---|---|
| ネイエ設計 | 230 枚 |
| ボックス・ワン | 15 枚 |
| **松尾工務店** | **6 枚**（物件概要テーブルが情報の主役） |

本制作は松尾工務店型（メイン写真 + 間取り図 + 物件概要テーブル + 本文）を採用しました。

**理由**: フリー素材では「同一物件の別カット」を複数枚揃えることが困難で、
無理に枚数を増やすと**別々の家の写真が並んで破綻する**ためです。
素材の制約と情報設計の両方に適合します。

### 間取り図はインライン SVG（自作）

ラスタ画像ではなく SVG にした理由:

- リクエストを増やさない（写真が主役のサイトなので転送量が効く）
- `currentColor` でテーマの配色に追従する
- 拡大しても劣化しない

**さらに、テンプレートに SVG を直書きせずデータから描画しています。**
直書きにすると施工実績を 1 件追加するたびにテーマファイルを編集することになり、
「運営者が自分で更新できる」という方針に反するためです。

管理画面では ACF のテキストエリアに 1 行 1 部屋で入力します。

```
LDK,0,0,6,4
洋室,6,0,3,3
和室,6,3,3,3
玄関,0,4,2,2
```

`室名,X,Y,幅,高さ`（マス目単位）。テーマ側の `sk_render_floor_plan()` が
数値を検証し、viewBox を自動計算して描画します。方位記号は右上に固定で描きます。
**不正な行は黙って捨てる**ため、入力ミスで画面が壊れることはありません。

## 6. 画像最適化（最重要要件）

トップページの `<img>` 枚数が業界中央値で 55 枚である以上、ここが品質を決めます。

### 実装

- **画像はすべてアイキャッチ / ACF image 経由で出力**
  `wp_get_attachment_image()` を使うことで `srcset` / `sizes` / `decoding` が自動付与されます。
  `<img src="...">` を手書きすると、この自動付与がすべて効きません。
- **`add_image_size()` で同じ縦横比の大中小を揃える**
  WordPress は元画像と同じ縦横比のサイズだけを `srcset` に載せます。
  1 サイズしか定義しないと `srcset` が育ちません。

  | 縦横比 | 定義したサイズ |
  |---|---|
  | 16:9 | `sk-hero-sm` 800×450 / `sk-hero-md` 1280×720 / `sk-hero` 1920×1080 |
  | 4:3 | `sk-thumb` 400×300 / `sk-card` 800×600 / `sk-card-lg` 1200×900 |
  | 3:2 | `sk-detail-md` 900×600 / `sk-detail` 1400×933 |

- **`sizes` を実際の表示幅で明示**
  既定の `100vw` のままだと、1/3 幅で表示されるカードにも全幅ぶんの画像が選ばれます。
- **ヒーローだけ `loading="eager"` + `fetchpriority="high"`、それ以外は `loading="lazy"`**
  LCP になる画像を遅延させると体感速度が落ちます。逆に、それ以外を遅延させないと帯域を無駄にします。
- **Web フォントを読み込まない**
  日本語 Web フォントはサブセットでも数百 KB あります。「帯域は写真に使う」という方針と矛盾するため、
  OS 標準の日本語ゴシックを使っています。
- ブロックエディタの既定 CSS（`wp-block-library`、約 100KB）と絵文字用スクリプトを解除。

### 実測値（トップページ / 1440×900 / キャッシュ無効 / Chrome）

`npm run verify` で計測。生データは `docs/verify/report.json`。

| 項目 | 実測 |
|---|---|
| リクエスト数 | **18 件** |
| 転送量 | **577 KB** |
| DOMContentLoaded | **527 ms** |
| load | **529 ms** |

内訳:

| 種別 | 件数 | 転送量 |
|---|---|---|
| 画像 | 10 件 | 545 KB |
| スクリプト | 5 件 | 14 KB |
| CSS 等 | 2 件 | 10 KB |

`<img>` 要素は 17 枚ありますが、**初期表示で読み込まれるのは 10 枚**です
（残り 7 枚は折り返しより下にあり遅延読み込み）。

| 検査項目 | 結果 |
|---|---|
| `srcset` 付与 | 17 / 17 枚 |
| `sizes` 付与 | 17 / 17 枚 |
| `loading="lazy"` | 16 枚 |
| `loading="eager"` + `fetchpriority="high"` | 1 枚（ヒーローのみ） |
| `loading` 属性なし | 0 枚 |

**`srcset` が実際に効いていることの確認**:
351×263px で表示される事業内容カードに対し、ブラウザが選んだのは
`service-newbuild-400x300.jpg`（1920px 版ではない）。

## 7. ヒーローのコントラスト（実測）

写真の上に白文字を置くため、コントラスト比 4.5:1 以上を**理論保証と実測の両方**で担保しています。

### 理論保証: スクリムの α 下限

文字が乗る領域の黒オーバーレイを **α 0.54 以上**にしています。
WCAG の相対輝度から逆算すると、黒 α ≧ 0.535 のとき、
背景が純白（相対輝度 1.0）でも白文字とのコントラストが 4.5:1 を上回ります。

| α | 合成後の輝度値 | コントラスト比 |
|---|---|---|
| 0.50 | 0.500 | 3.98 ✗ |
| **0.535** | 0.465 | **4.51** ✓ |
| 0.54 | 0.460 | 4.59 ✓ |

**写真を差し替えても破綻しない**のがこの方式の利点です。
実装ではヒーロー下部 75% を α 0.60 以上に保ち、文字は必ずその内側に配置しています。

### 実測: 合成後の画素をサンプリング

「たまたま今の写真で満たした」ではないことを確かめるため、実ブラウザで測定しています。
**文字を一時的に非表示にしてから撮影**し（表示したまま撮ると白い文字自体を背景として拾ってしまう）、
文字の外接矩形を格子状に 40 点サンプリングして、
**最も明るい画素**（白文字にとっての最悪値）でコントラスト比を算出します。

| 対象 | サンプル数 | 最明画素 | 相対輝度 | コントラスト比 |
|---|---|---|---|---|
| ヒーロー（1440px） | 40 点 | rgb(76,77,77) | 0.0738 | **8.48 : 1** |
| ヒーロー（390px） | 40 点 | rgb(62,64,66) | 0.0508 | **10.41 : 1** |
| 採用バナー（1440px） | 40 点 | rgb(84,78,68) | 0.0775 | **8.23 : 1** |
| 採用バナー（390px） | 40 点 | rgb(79,79,79) | 0.0782 | **8.19 : 1** |

いずれも基準の 4.5:1 を上回っています。

## 8. フォーム（Contact Form 7 と自作の使い分け）

本サイトでは **Contact Form 7** を使っています（お問い合わせ / 採用応募の 2 種）。
実サイト 50 件で最多（42%）のプラグインであり、既存案件の改修を引き継げることに価値があるためです。

**別途公開しているポートフォリオ（`portfolio_wordpress`）ではフォームを自作しています。**
両方扱えることを示すために、あえて実装を変えました。

| | 長所 | 向いている場面 |
|---|---|---|
| Contact Form 7 | 発注者が管理画面から項目を変更できる | 項目が変わる可能性がある / 運用を発注者が行う |
| 自作 | 依存が減り軽い。バリデーションを完全に制御できる | 項目が固定 / 依存を増やしたくない |

- 送信メッセージは日本語を明示して保存しています（CF7 の既定は翻訳ファイル依存で、
  CLI から作成すると英語のまま保存されることがあるため）。
- ショートコードは ACF フィールドに入れているため、フォームを作り直しても
  テンプレートを書き換える必要がありません。

### ローカルでの送信確認

素の WordPress コンテナには MTA が無く `mail()` が外に出ません。
CF7 は「送信しました」と表示しますが、実際にはメールが生成されず、
**「フォームが送信できる」を検証できません。**

そのため `docker compose` に **Mailpit** を同梱し、mu-plugin で SMTP を向けています。

- 受信箱: http://localhost:8035
- 差し替えは `wp_get_environment_type() === 'local'` のときだけ実行するため、
  **レンタルサーバーへ移設してもファイルを消す必要がなく、標準の `mail()` に戻ります**
- WP Mail SMTP 等のプラグインは追加していません（`phpmailer_init` フックで同じことができるため）

`npm run verify` が実際にフォームを送信し、Mailpit の受信箱に届いたことまで自動で確認します。

## 9. 使用プラグインと、その理由

**プラグインは 3 つだけです。**
CrowdWorks の実案件に「WordPress で保守・運用の費用が掛からないようなホームページ作成を希望します」
という記載がありました。プラグインを増やすほど、更新・互換性・脆弱性の面倒が増えます。

| プラグイン | 区分 | 採用理由 |
|---|---|---|
| Advanced Custom Fields | 無料版 | 施工実績の物件情報と各ページの文言を管理画面から編集可能にするため |
| Contact Form 7 | 無料 | 実サイト 50 件で最多（42%）。発注者が項目を変更できる |
| **koumuten-core** | 自作 | CPT / タクソノミー / フィールド定義 / 会社情報設定 |

**入れなかったもの**:

| プラグイン | 代わりにしたこと |
|---|---|
| SEO 系（Yoast / All in One SEO） | `inc/seo.php` で description・OGP・構造化データを自前出力 |
| WP Mail SMTP | mu-plugin で `phpmailer_init` をフック |
| キャッシュ系 | `.htaccess` に `mod_expires` の設定を追記（共用サーバーでも標準で有効） |
| ページビルダー | オリジナルテーマ（実サイト調査で既製テーマは 0 件） |

### ACF 無料版で完結させている

ACF Pro（有料）を使わない構成にしています。発注者に追加コストを負わせないためです。
Pro 機能の代替は次のとおりです。

| Pro 機能 | 代替 |
|---|---|
| Repeater（可変長） | textarea に 1 行 1 レコード（`項目,値`）で入力し、テーマ側でパース |
| Repeater（件数固定） | `group` フィールドに固定個のサブフィールド（Instagram の 6 枚など） |
| Options Page（サイト共通設定） | **カスタマイザー**の「会社情報」セクション（登録はプラグイン側） |

textarea 方式は入力フォーマットのミスに弱いため、各フィールドの説明欄に記入例を必ず記載し、
パーサは不正な行を捨てて落ちないようにしています。

## 10. Instagram セクション（API を使っていません）

トップページの Instagram セクションは、**公式 API を使わずに実装しています。**

**理由**:

1. Instagram Basic Display API は **2024 年 12 月に提供終了**
2. oEmbed は Meta のアプリ審査（`oembed_read`）が必要で、審査を通らないと表示できない
3. そもそも本サイトは架空企業のため、実アカウントが存在しない

**実装**: ACF で登録した 6 枚のグリッド + アカウントへの外部リンク。
写真は施工実績のものを流用しています（管理画面から差し替え可能）。

### 実アカウント運用時の差し替え手順

1. Meta for Developers でアプリを作成し、`oembed_read` の審査を通す
2. または埋め込みサービス（SnapWidget / Instafeed 等）のウィジェットを利用する
3. `template-parts/section-instagram.php` のグリッド出力部分を置き換える
   （見出し・リード文・外部リンクの実装はそのまま流用できます）

なお、外部ウィジェットは JavaScript を読み込むため転送量が増えます。
本サイトの「画像最適化を最優先する」方針とは競合する点に注意してください。

## 12. 管理画面から編集できる箇所

## 13. ハードコードしている箇所と、その理由

「運営者が自分で更新できる範囲を最大化する」方針のもと、
お知らせ・施工実績・募集要項・営業時間・電話番号・トップの各セクション文言は
すべて管理画面から編集できます。その上で、**意図的にハードコードしている箇所**は次のとおりです。

| 箇所 | 内容 | 理由 |
|---|---|---|
| `footer.php` | 「本サイトは架空の企業を想定した制作サンプルです」の 1 行 | **編集可能にすると運営者が消せてしまい、架空である明示の意味が無くなるため** |
| `inc/template-tags.php` の `sk_sample_notice()` | 施工実績のサンプル表記 | 同上 |
| `inc/template-tags.php` の `sk_nav_fallback()` | メニュー未設定時の代替リンク | 納品直後にメニュー未設定でもナビが消えないようにする保険 |
| `template-parts/section-access.php` ほか | 「住所はダミーのため、地図は姫路駅周辺を表示しています」 | 同上（誤認防止） |
| `plugins/koumuten-core/inc/post-types.php` | タクソノミーの初期ターム | 有効化時の初期値。管理画面から追加・削除・改名できる |

## 15. レンタルサーバーへの移設手順

ロリポップ / エックスサーバー等の共用サーバーを想定しています。
サーバー固有の機能に依存せず、パスもハードコードしていません
（`home_url()` / `get_template_directory_uri()` を使用）。

1. **WordPress を新規インストール**（サーバーの簡単インストールで可）
2. **テーマとプラグインをアップロード**
   - `themes/soranowa-koumuten/` → `wp-content/themes/`
   - `plugins/koumuten-core/` → `wp-content/plugins/`
   - `mu-plugins/local-smtp.php` → `wp-content/mu-plugins/`
     （`WP_ENVIRONMENT_TYPE` が `local` 以外では何もしないため、そのまま置いて問題ありません）
3. **ACF と Contact Form 7 を管理画面から導入**して有効化
4. **`koumuten-core` を有効化** → CPT のリライトルールが登録されます
5. **テーマを有効化**
6. **パーマリンク設定を「投稿名」にして保存**
   これを忘れると `/works/{slug}/` が 404 になります
7. **「設定 > 表示設定」** でフロントページと投稿ページを割り当て
8. **「外観 > カスタマイズ > 会社情報」** で電話番号・住所・営業時間・地図 URL を設定
9. `.htaccess` に `config/htaccess-cache.conf` の内容を追記（任意）

### 移設時の注意

- ローカルの DB をそのまま移す場合は、URL の置換が必要です
  （`wp search-replace 'http://localhost:8090' 'https://example.com'`）
- 画像は `wp-content/uploads/` ごと移し、必要なら `wp media regenerate` でサイズを再生成します
- メール送信は移設先の標準の `mail()` に切り替わります。届かない場合は
  サーバー側の送信元ドメイン制限（SPF）を確認してください

## 16. コード品質

- WordPress Coding Standards に準拠
- 出力は必ずエスケープ（`esc_html()` / `esc_attr()` / `esc_url()` / `wp_kses()`）
  未エスケープの出力は 3 箇所のみで、いずれも意図的なもの（`phpcs:ignore` と理由を明記）
  — `wp_get_attachment_image()` の戻り値、CF7 のショートコード出力
- 入力はサニタイズ（カスタマイザーの全設定に `sanitize_callback` を指定）
- DB アクセスは `WP_Query` / `get_posts()`。生 SQL の文字列連結なし
- アーカイブの表示件数変更は `pre_get_posts` で行い、テンプレート側で `WP_Query` を作り直していない
  （作り直すとページネーションがメインクエリとずれます）
- `WP_DEBUG` を有効にした状態で、PHP エラー・WordPress の警告は出ていません

### 実装中に踏んだ不具合（記録）

日本語サイトで踏みやすい落とし穴として記録しておきます。

**`preg_split('/\R/', $text)` が日本語を壊す。**
`\R` は `u` 修飾子が無いとバイト `0x85`（NEL）1 文字にもマッチします。
UTF-8 の日本語には `0x85` を含む文字が多く（者 = `E8 80 85`、入 = `E5 85 A5`、内 = `E5 86 85`）、
**文字の途中で行が割れて文字化けします**。
`/\r\n|\r|\n/` を明示すれば、UTF-8 は自己同期符号なので安全に分割できます。

## 19. SEO / アクセシビリティ

- `<title>` は `add_theme_support('title-tag')` で WordPress に生成させ、テンプレートに直書きしていません
- meta description / OGP / Twitter Card を全ページで出力
- 構造化データ（JSON-LD）: `GeneralContractor`（工務店向けの LocalBusiness サブタイプ）/
  `BreadcrumbList` / `Article`
- パンくずは画面表示と構造化データで同じデータ（`sk_breadcrumb_items()`）を使用
- 施工実績の絞り込みは JavaScript の表示切替ではなく**タクソノミーアーカイブへのリンク**。
  絞り込んだ状態に URL が付き、共有・ブックマーク・検索流入ができます
- 見出し階層は各ページで h1 が 1 つ
- すべての `<img>` に代替テキスト。テンプレートで固定せずメディアライブラリの値を使うため、
  運営者が管理画面から編集できる（全 11 ページ 31 枚で alt が空のものは 0 件）
- スキップリンク / `aria-expanded` / `aria-current` / `role="img"` + `<title>`（間取り図 SVG）
- タップ領域: ボタン・ナビ・フォーム部品などの主要な操作要素は 44×44px 以上。
  パンくずや文中のリンクは、行の高さに制約されるため WCAG 2.5.8（AA）の下限である
  24×24px 以上（パンくずを 44px にすると帯だけで 68px を占め、モバイルで本文が押し下げられるため）。
  全 11 ページ・390px 幅で 24px 未満の操作要素が 0 件であることを `npm run verify` で検証
- `prefers-reduced-motion` に対応
